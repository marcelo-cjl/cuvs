# GPU 内存变化示意图

本文档描述 Knowhere/cuVS 在典型使用场景下的 GPU 内存变化过程。

## 配置参数

| 参数 | 值 |
|------|-----|
| Workspace Pool 最大值 | 6G |
| Workspace Pool 初始值 | 1G |
| Main Pool 最大值 | 6G |
| Main Pool 初始值 | 2G |

---

## 图 1: 初始化后 (`initialize_raft()`)

```
                    GPU 显存 (地址从左到右递增)
    ┌────────────────────────────────────────────────────────────────────┐
    │▓▓▓▓▓▓▓▓│                                                           │
    │Workspace                          可用空间                          │
    │ Pool 1G│                           ~12G                            │
    └────────────────────────────────────────────────────────────────────┘
     ~~~~~~~~
       1GB
```

- Workspace Pool 初始化 1G
- Main Pool 尚未创建

## 图 2: Build 索引 a (2G)

```
                    GPU 显存
    ┌────────────────────────────────────────────────────────────────────┐
    │▓▓▓▓▓▓▓▓│████████████████│                                          │
    │Workspace    索引 a                    可用空间                       │

    └────────────────────────────────────────────────────────────────────┘
     ~~~~~~~~ ~~~~~~~~~~~~~~~~
       1GB        2GB
              (cudaMalloc)
```

- 索引 a 通过 `cudaMalloc` 直接分配，**不在 Main Pool 中**

## 图 3: Search 触发 Main Pool 创建 (2G)

```
                    GPU 显存
    ┌────────────────────────────────────────────────────────────────────┐
    │▓▓▓▓▓▓▓▓│████████████████│                         │▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒│                        │
    │Workspace    索引 a                  可用空间             Main Pool   │                 │
    │ Pool 1G│      2G        │            ~7G          │      2G        │                   │
    └────────────────────────────────────────────────────────────────────┘
     ~~~~~~~~ ~~~~~~~~~~~~~~~~ ~~~~~~~~~~~~~~~~~~
       1GB        2GB               2GB
              (cudaMalloc)     (0x708c68000000)
```

- Search 调用 `get_device_resources()` 触发 Main Pool 创建
- Main Pool 地址: `0x708c68000000`

## 图 4: 释放索引 a

```
                    GPU 显存
    ┌────────────────────────────────────────────────────────────────────┐
    │▓▓▓▓▓▓▓▓│                                          │▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒│
```

## 图 5: Build 索引 b (4G) - Main Pool 扩展

索引 b 需要 4G，Main Pool 当前只有 2G，需要扩展。

```
                    GPU 显存
    ┌────────────────────────────────────────────────────────────────────┐
    │▓▓▓▓▓▓▓▓│▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒│                         │▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒│
    │Workspace        Main Pool               可用空间        │   Main Pool │
    │ Pool 1G│       4G 索引b         │          4GB         │      2G     │
    └────────────────────────────────────────────────────────────────────┘
     ~~~~~~~~ ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~         ~~~~~~~~~~~~~~~~~~
       1GB              4GB                                  2GB
              (0x708a66000000)                        (0x708c68000000)
                    │                                        │
                    │◄─────────── 地址不连续 ───────────────►│
                    │         中间有 ~4GB 空洞               │
```

**关键**: 新分配的 4G 块地址 (`0x708a66`) 比原 2G 块 (`0x708c68`) **更低**，两块不连续!

## 图 6: 释放索引 b - Main Pool 碎片化

```
                    GPU 显存
    ┌────────────────────────────────────────────────────────────────────┐
    │▓▓▓▓▓▓▓▓│░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░│        │░░░░░░░░░░░░░░░░│
    │Workspace   Main Pool 块2 (空闲)         │  空洞  │Main Pool 块1   │
    │ Pool 1G│           4G                   │ ~4GB  │  2G (空闲)     │
    └────────────────────────────────────────────────────────────────────┘
     ~~~~~~~~ ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~         ~~~~~~~~~~~~~~~~~~
       1GB              4GB                                  2GB
              (0x708a66000000)                        (0x708c68000000)

    ┌─────────────────────────────────────────────────────────────────────┐
    │ Main Pool 状态:                                                     │
    │   • 总容量: 6G (已达最大值)                                          │
    │   • 总空闲: 6G                                                      │
    │   • 块 1: 2G @ 0x708c68 (空闲)                                      │
    │   • 块 2: 4G @ 0x708a66 (空闲)                                      │
    │   • 最大连续块: 4G  ⚠️                                               │
    └─────────────────────────────────────────────────────────────────────┘
```

索引 b 释放后，4G 返回 Main Pool，但两块**无法合并** (地址不连续)

## 总结

| 阶段 | Workspace | Main Pool | 索引占用 | 问题 |
|------|-----------|-----------|---------|------|
| 初始化 | 1G | - | - | - |
| Build a | 1G | - | 2G (cudaMalloc) | - |
| Search | 1G | 2G | 2G | - |
| 释放 a | 1G | 2G | - | 产生地址空洞 |
| Build b | 1G | 2G + 4G = 6G | 4G | 两块不连续 |
| 释放 b | 1G | 6G (碎片化) | - | 最大连续块 4G |
| Build c | 1G | 6G | ❌ 失败 | 需要 5G 连续块 |

**根本原因**: Build 在 Search 之前执行时，使用 `cudaMalloc` 而非 Main Pool，导致后续 Main Pool 扩展时地址不连续，产生碎片化。
